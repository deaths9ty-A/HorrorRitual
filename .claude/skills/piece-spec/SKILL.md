# สเปกและโครงระบบของหนึ่งชิ้น

**เหตุผล:** ออกแบบโครงระบบก่อนลงมือทำให้ชิ้นที่ต่อกันไม่ชนกัน และเจ้าของเห็นภาพรวมก่อนตัดสินว่า "ทำ"

## เช็กลิสต์ (คัดลอกไปติ๊ก)
```
- [ ] 1 บรีฟ 7 ช่องครบ และเจ้าของตอบ "ตรง" แล้ว (ดู intake)
- [ ] 2 จัดขนาดงาน: เล็ก หรือ ชิ้น
- [ ] 3 เขียนโครงระบบก่อนโค้ด
- [ ] 4 เขียนสเปกตามแม่แบบ จบด้วย รอคำว่า "ทำ"
- [ ] 5 หลัง "ทำ": อ่านเอกสาร Godot แล้วบอกหน้าที่อ่าน
- [ ] 6 สร้างทีละขั้นตามโครงระบบ ตรวจทุกขั้นก่อนไปขั้นถัดไป
- [ ] 7 เทสกันพัง + ถ่ายภาพจริง (บนเครื่องที่มี Godot 4.8-dev7)
- [ ] 8 ส่งต่อ report-result แล้วรอเจ้าของเล่น
```

## จัดขนาดงาน
- **เล็ก** (แก้ค่า แก้ข้อความ แก้บั๊กจุดเดียว): สเปก 3 บรรทัด คือ ทำอะไร · ไฟล์ที่แตะ · วิธีตรวจ
- **ชิ้น** (ฟังก์ชันหรือระบบใหม่): ใช้แม่แบบเต็มข้างล่าง
- งานที่ขยายระหว่างทาง ให้ย้ายขึ้นเป็น "ชิ้น" และกลับมาขอ "ทำ" อีกครั้ง

## โครงระบบ (ทำก่อนเขียนโค้ดทุกชิ้น)
- ไฟล์ใหม่ และไฟล์เดิมที่แตะ
- โหนด ซีน สัญญาณ ที่ใช้
- จุดต่อกับของเดิม (ระบบผู้เล่น มอน เสียง เมนู)
- ขั้นสร้าง 3–6 ขั้น แต่ละขั้นมีวิธีตรวจของตัวเอง

## แม่แบบสเปก (ครึ่งหน้า)
```
ชิ้น: <ชื่อ>
ทำอะไร: <1–2 ประโยค>
อ้าง LN ตรงไหน: <LN ทำยังไง + ลิงก์ · แหล่งเดียวเขียน "ต้องยืนยันเพิ่ม">
ค่าจากเจ้าของ: <รายการ>
ค่าเริ่มที่ Claude ตั้ง: <รายการ + เหตุผลสั้น ๆ · ปรับได้ใน Inspector (@export)>
โครงระบบ: <ไฟล์ · โหนด · จุดต่อ · ขั้นสร้าง>
เอกสาร Godot ที่จะอ่าน: <หน้า / ชื่อคลาส>
วิธีตรวจ: <เทสกันพังตัวไหน · ภาพที่จะถ่าย · FPS เทียบเกณฑ์ 60>
เจ้าของเล่นแล้วตัดสิน: <ความรู้สึกหรือเกณฑ์ที่เจ้าของจะดู>
งานเดิมที่กระทบ: <ไฟล์ที่เจ้าของแก้ไว้ + วิธีเก็บไว้ครบ เช่น สร้างไฟล์ใหม่ข้างไฟล์เดิม>
```
จบสเปกด้วยบรรทัด: `รอคำว่า "ทำ"`
