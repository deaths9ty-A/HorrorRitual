# เสนอทางเลือกและคุมโฟกัส

**เหตุผล:** เจ้าของเลือกได้ดีเมื่อมีทางที่จัดวางไว้ให้เลือก และคิดภาพกว้างจนหลุดโฟกัสได้ง่าย ผมจึงเสนอทางเลือกเต็มที่แล้วให้เจ้าของเป็นคนตัดสินดีไซน์

## เช็กลิสต์ (คัดลอกไปติ๊ก)
```
- [ ] 1 หัวคำตอบ: "โฟกัสตอนนี้: <ชิ้น/เรื่อง>"
- [ ] 2 แยกที่มาของค่า: เจ้าของกำหนด / มีแหล่งอ้างอิง / ค่าเริ่มที่ Claude ตั้ง
- [ ] 3 เสนอทางเลือก 2–3 ข้อ ติดป้าย (Claude เสนอ)
- [ ] 4 จบด้วยข้อแนะนำหนึ่งข้อ + เหตุผลหนึ่งบรรทัด
- [ ] 5 ถามให้เลือกครั้งละหนึ่งเรื่อง
- [ ] 6 ท้ายคำตอบ: "เรื่องที่ยังเปิดอยู่" (ไม่เกิน 5 ข้อ จาก INDEX.md)
- [ ] 7 เมื่อเจ้าของตัดสินแล้ว จดเป็น #ตัดสินแล้ว ผ่าน intake แล้วส่งต่อ piece-spec
```

## ทางเลือกแต่ละข้อ (เสนอแบบขายตรง ๆ)
- **ชื่อสั้น** ที่จำง่าย
- **ภาพ:** เจ้าของจะเห็นหรือรู้สึกอะไรตอนเล่น
- **ข้อดี**
- **ข้อแลก** (บอกครบเสมอ เพื่อให้การเสนอไม่เอนเอียง)
- **กลับตัวได้ไหม** และแก้ยากแค่ไหน

เมื่อเจ้าของลังเล ให้ "ค่าเริ่มต้น": เริ่มที่ทางที่แนะนำ ลองแล้วเปลี่ยนได้ แล้วบอกว่าจะรู้ได้อย่างไรว่าควรเปลี่ยน

## คุมโฟกัส
- เรื่องใหม่ที่โผล่กลางทาง จดเป็น #จอดไว้ ใน docs/office/ แล้วถามว่า "คุยตอนนี้หรือจอดไว้ก่อน"
- ก่อนค้นข้อมูล เขียนหนึ่งบรรทัดว่าจะค้นอะไรเพื่อตอบคำถามไหน
- แหล่งอ้างอิงมีลิงก์ ถ้ามีแหล่งเดียวเขียน "ต้องยืนยันเพิ่ม" ถ้าเปิดไม่ได้ก็บอก
